# Repository agent instructions

This repository uses a Project Continuity System so work can continue across conversations without repeating completed setup or losing the current roadmap state.

Before making meaningful changes:

1. Inspect the directly verifiable current state first: relevant files and repository working tree, Git/GitHub state, platforms, accounts, resources, and relevant technical evidence. Validated lab documentation and Git history are part of that verifiable evidence.
2. Reconcile the observed state with `PROJECT-STATUS.md` and, when available locally, the current `PROJECT-CONTEXT.md`; treat them as summarized operational checkpoints, not substitutes for direct verification.
3. Read `ROADMAP.md` for the long-term sequence, priorities, future direction, and portfolio standards.
4. Read `docs/PROJECT-CONTINUITY-PROTOCOL.md` for the working method, safety rules, and continuity expectations.
5. Consult relevant lab, module, or course documentation when applicable, and interpret it against the directly verified state.
6. Use conversation history and memory only as supporting context, not as a source of truth when verifiable evidence exists.
7. Preserve completed labs and existing evidence unless a requested change intentionally updates them.
8. Do not publish private/raw evidence, credentials, identifiers, secrets, or sensitive logs.
9. Do not present simulated or self-directed work as production employment experience.
10. Prefer one safe, verifiable step at a time for practical work.
11. Evaluate costs and recurring-charge risks before suggesting or activating paid/cloud resources.
12. Update `PROJECT-STATUS.md` whenever the verified project state materially changes.

A new chat or device does not reset the project. Continue from the repository and current verified state instead of asking the user to reconstruct previously documented progress.
