# Repository agent instructions

This repository uses a Project Continuity System so work can continue across conversations without repeating completed setup or losing the current roadmap state.

Before making meaningful changes:

1. Read `PROJECT-STATUS.md` for the current checkpoint and immediate next action.
2. Read `ROADMAP.md` for the long-term sequence and portfolio standards.
3. Read `docs/PROJECT-CONTINUITY-PROTOCOL.md` for the working method, safety rules, and continuity expectations.
4. Inspect the actual relevant files before assuming a lab/module is missing or incomplete.
5. Preserve completed labs and existing evidence unless a requested change intentionally updates them.
6. Do not publish private/raw evidence, credentials, identifiers, secrets, or sensitive logs.
7. Do not present simulated or self-directed work as production employment experience.
8. Prefer one safe, verifiable step at a time for practical work.
9. Evaluate costs and recurring-charge risks before suggesting or activating paid/cloud resources.
10. Update `PROJECT-STATUS.md` whenever the verified project state materially changes.

A new chat or device does not reset the project. Continue from the repository and current verified state instead of asking the user to reconstruct previously documented progress.
